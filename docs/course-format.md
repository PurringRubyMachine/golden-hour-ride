# Course format, version 1

A course is a folder under `courses/<id>/`. The app fetches its files when a rider picks it, so adding a course needs no code. Two validators check courses against this document:

- `src/course/validate.js`, used by the app and the JavaScript unit tests;
- `tools/coursebuilder/validate.py`, used by the course builder and `python -m tools.coursebuilder validate`.

They give the same answers; `tests/course-cases.json` keeps them in step. If you change the format, change this document, both validators and the shared cases together.

## Folder

```
courses/
  index.json            every course, for the menu
  <id>/
    course.json         required
    terrain.bin         survey courses: ground heights
    road.json           survey courses: the road line
    scenery.json        optional: buildings, trees, hedges and walls, woodland
    ground.jpg          optional: the ground photographed from above
    build.json          written by the course builder: where the course came from (the app ignores it)
    route.gpx           optional: the route, if the builder was asked to keep it (--keep-route)
    README.md           optional: notes on the course and its sources
```

The app reads only the first five. `build.json` records the build: the command (paths relative to the project, or bare file names), the GPX's SHA-256 and whether it was kept, the working coordinate system and the DTM files by name, and how current the OpenStreetMap data was (`openStreetMap.dataAsOf`, Overpass's timestamp). It isn't checked by the validators, so it isn't part of format 1.

`<id>` is lower-case letters, digits and hyphens, such as `leckhampton` or `mont-ventoux-bedoin`. It is what `?course=<id>` takes.

## Local frame

Survey courses are in local metres around the centre of the terrain square: **x east, y up, z south**. The origin's position in a real coordinate system is recorded in `course.json` (`origin`), so a course can be related back to a map, but the app never needs it.

## course.json

```json
{
  "format": 1,
  "id": "leckhampton",
  "name": "Leckhampton Hill loop",
  "shortName": "Leckhampton",
  "description": "A loop over the Cotswold scarp above Cheltenham, past the old quarries on Leckhampton Hill.",
  "kind": "survey",
  "loop": true,
  "start": 850,
  "origin": { "crs": "EPSG:27700", "x": 395640, "y": 218870 },
  "terrain": { "file": "terrain.bin", "size": 6200, "cells": 620, "min": 44.68, "max": 297.98 },
  "road": "road.json",
  "scenery": {
    "file": "scenery.json",
    "style": "pastoral-1800s",
    "options": { "sheepAbove": 175, "stooksBelow": 150, "smoke": [[-962.5, 464.9]] }
  },
  "credits": [
    {
      "text": "Heights: Environment Agency LiDAR, Open Government Licence.",
      "licence": "OGL-UK-3.0",
      "url": "https://environment.data.gov.uk/survey"
    }
  ]
}
```

| Field         | Required        | Meaning                                                                                                                              |
| ------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `format`      | yes             | `1`.                                                                                                                                 |
| `id`          | yes             | The folder's name.                                                                                                                   |
| `name`        | yes             | Shown in the course menu and the loading message.                                                                                    |
| `shortName`   | no              | For the course button and the ride log. `name` is used if it's missing.                                                              |
| `description` | no              | A sentence about the course.                                                                                                         |
| `kind`        | yes             | `"survey"` (built from real data) or `"procedural"` (generated by the app).                                                          |
| `generator`   | procedural only | Which generator: `"valley"` is the only one.                                                                                         |
| `loop`        | yes             | `true`. Format 1 supports loops only: the ride carries on round from the end to the start.                                           |
| `start`       | no              | Where riders begin, in metres along the loop from the road's first point. Default `0`.                                               |
| `origin`      | survey only     | `{ "crs", "x", "y" }`: the terrain square's centre in a coordinate system with an EPSG code (or a full definition), in its units.    |
| `terrain`     | survey only     | `{ "file", "size", "cells", "min", "max" }`: see [terrain.bin](#terrainbin).                                                         |
| `road`        | survey only     | The road file's name: see [road.json](#roadjson).                                                                                    |
| `scenery`     | no              | `{ "file"?, "style", "options"? }`: see [Scenery](#scenery).                                                                         |
| `imagery`     | no              | `{ "file", "size" }`: a photo of the ground from above; see [ground.jpg](#groundjpg).                                                |
| `credits`     | yes             | A list of `{ "text", "licence", "url"? }`. The texts are shown on screen, joined by spaces. Survey courses must credit every source. |

A procedural course has only `format`, `id`, `name`, `shortName`, `description`, `kind`, `generator`, `loop`, `start` and `credits` (which may be empty: there is no outside data to credit).

### Credits

Every source of data in the course needs an entry: the heights, the route if it came from someone else's map, and OpenStreetMap if the scenery came from there. `licence` is an [SPDX identifier](https://spdx.org/licenses/) where one exists (`OGL-UK-3.0`, `OGL-Canada-2.0`, `ODbL-1.0`, `CC-BY-4.0`, `etalab-2.0`), and otherwise the licence's name. The course builder writes the OpenStreetMap credit itself.

## terrain.bin

The ground as a square grid of heights: `(cells + 1) × (cells + 1)` points, `size / cells` metres apart (the builder uses 10 m), covering `size` metres from `-size/2` to `+size/2` in x and z.

- Little-endian unsigned 16-bit integers, `(cells + 1)²` of them, row by row.
- Row 0 is the north edge (z = `-size/2`); each row runs west to east.
- A value `v` is a height of `min + v / 65535 × (max − min)` metres.

The heights come from the DTM, each the average over its cell. The app smooths the ground next to the road into the road's own heights.

## road.json

The road's centre line: `[[x, y, z], ...]` in local metres, one point about every 15 m, in the direction of travel. The last point joins back to the first. `y` is the road surface's height, smoothed. The app draws a smooth curve through the points.

At least 4 points; every point must be inside the terrain square.

## Scenery

`scenery.style` chooses how the course is dressed:

- `"plain"`: trees from the woodland mask and single trees, hedges and walls, nothing else.
- `"pastoral-1800s"`: as plain, plus flocks of sheep on high ground and fields of hay stooks in the vale. This is how Leckhampton looks.

`scenery.options`, all optional:

| Option        | Meaning                                                                                                   |
| ------------- | --------------------------------------------------------------------------------------------------------- |
| `sheepAbove`  | Pastoral: sheep graze beside the road where it is above this height, in metres.                           |
| `stooksBelow` | Pastoral: hay fields line the road where it is below this height.                                         |
| `smoke`       | `[[x, z], ...]`: smoke rises from the steepest ground within about 260 m of each point, such as a quarry. |

### scenery.json

Optional, and every key in it is optional. All positions are local metres.

| Key         | Entries                                     | Meaning                                                                                                                                                                                 |
| ----------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `buildings` | `[x, z, width, depth, angle, height, roof]` | A building's footprint as a rectangle centred on (x, z), `angle` radians from the x axis towards z; `height` metres to the eaves; `roof` 1 for pitched, 0 for flat. See the note below. |
| `trees`     | `[x, z]`                                    | A single tree.                                                                                                                                                                          |
| `lines`     | `[x1, z1, x2, z2, kind]`                    | A piece of hedge (`kind` 0) or wall (`kind` 1), up to about 6 m long.                                                                                                                   |
| `woods`     | base64 text                                 | Woodland: one bit per terrain grid point, in terrain.bin's order, least significant bit first, base64-encoded. Woods are filled with trees. An empty string means none.                 |

Note: the app doesn't draw buildings yet. They're switched off for Leckhampton's 19th-century look (`SHOW_TOWN` in `src/scenery/buildings.js`), and for now they only keep trees off them. They're kept in the data so that a future scenery style can draw them.

## ground.jpg

Optional: the terrain square photographed from above (an aerial photo or a satellite image), which the app shows in the distance in place of the ground's own colours. `course.json` names it in `imagery`: `{ "file": "ground.jpg", "size": 4096 }`.

- A JPEG, `size` × `size` pixels, covering the terrain square exactly: row 0 is the north edge, each row runs west to east, as in `terrain.bin`. The builder makes it a power of two at most 4096 across, at about 4 m per pixel or finer.
- Its brightness evened out (the builder stretches it to a common range) so photos from different sources look alike in the scene.
- Its source credited in `credits`, like every other source.

## index.json

The course menu's list, in the order shown. The valley comes first: it is the default.

```json
[
  { "id": "valley", "name": "The valley", "shortName": "Valley", "lengthKm": 3.3, "climbM": 70 },
  { "id": "leckhampton", "name": "Leckhampton Hill loop", "shortName": "Leckhampton", "lengthKm": 11.9, "climbM": 228 }
]
```

`name` and `shortName` must match the course's own; `lengthKm` and `climbM` are the loop's length and total climbing, from road.json. The course builder keeps the index up to date. The unit tests check that every folder is listed, once, and nothing else.

## Size

The terrain is about 0.75 MB for a 6 km square, and a road line a few tens of kilobytes. Scenery from OpenStreetMap is a few hundred kilobytes in the countryside. A photo of the ground is at most about 2.5 MB (the builder lowers its quality to fit). Keep a course under about 5 MB, plus the photo: a larger terrain square (a long route) is the usual cause, and a smaller `--margin` the usual cure.

## What may change

A later format may allow point-to-point routes (`"loop": false`) and more scenery styles. A course in format 1 will keep working: the app will read `format` and treat each version as written.
